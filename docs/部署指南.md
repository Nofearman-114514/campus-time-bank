## 1. 前置准备

### 1.1 注册小程序账号

| 步骤 | 操作 |
|---|---|
| 1 | 打开 <https://mp.weixin.qq.com> → 右上角「立即注册」→ 选择「小程序」 |
| 2 | 用一个**没有注册过公众平台**的邮箱注册，设置密码 |
| 3 | 主体类型选「个人」，用本人微信扫码做身份验证 |
| 4 | 注册完成后登录，进入「开发管理 → 开发设置」，记下 **AppID（小程序 ID）** |

> **也可以用测试号先跑通。** 测试号不需要注册小程序账号，直接用微信扫码登录
> <https://mp.weixin.qq.com/wxamp/sandbox?doc=1> 即可获得一个 `wx` 开头的 AppID。
> 但测试号**不能使用云开发的部分开放接口**（如手机号快速验证），也不能发布上线。
> 如果只是本地跑通、录演示视频，测试号够用；如果要答辩时用体验版给老师扫码，
> 建议还是注册正式的小程序账号（个人主体免费，无需企业资质）。

### 1.2 下载微信开发者工具

1. 打开 <https://developers.weixin.qq.com/Campus Time Bank/dev/devtools/download.html>
2. 下载 **稳定版 Stable Build** 的 Windows 64 位安装包
3. 安装后首次打开，用微信扫码登录

> 本项目使用的是原生小程序 + 云开发，对开发者工具版本没有特殊要求，
> 建议 **1.06.2405020 及以上**（`project.config.json` 里声明的基础库版本是 `3.5.8`）。
>
> 若打开项目时提示「**下载基础库版本失败**」，到 **详情 → 本地设置 → 调试基础库**
> 里改成你本机已下载的版本即可。本项目用到的**新**能力只有两个：
> `open-type="chooseAvatar"` 与 `<input type="nickname">`（均需 **2.21.2+**），
> 其余如 `wx.getWindowInfo`(2.20.1+)、`wx.chooseMedia`(2.10.0+) 要求更低。
> 因此**任意 ≥ 2.24 的基础库都能完整跑通**，不需要追新。

### 1.3 开通云开发

1. 打开项目后，点击开发者工具顶部工具栏的「**云开发**」按钮
2. 弹出开通引导 → 同意《微信云开发服务协议》→ 点击「开通」
3. **环境名称**随便取（如 `campus-time-bank`），**环境 ID** 会自动生成（形如 `campus-time-bank-1g2h3i4j5k6l7m`）

2. **目录**选择本项目根目录（含 `project.config.json` 的那一层）

> ```json

> "cloudfunctionRoot": "cloudfunctions/"
> ```

### 2.2 把 `touristappid` 换掉

仓库里的 `project.config.json` 中 `appid` 字段是占位的游客 AppID：

```json
{
  "miniprogramRoot": "Campus Time Bank/",
  "cloudfunctionRoot": "cloudfunctions/",
  "appid": "touristappid",     ← 这里是占位值
  "projectname": "campus-time-bank"
}
```

**两种改法，任选其一：**

| 方式 | 做法 | 推荐度 |
|---|---|---|
| A. 在工具里改（推荐） | 开发者工具 → 右上角「详情」→「基本信息」→ 修改 AppID → 填入自己的 AppID | ★★★ 不用手改文件，工具会自动写回 `project.config.json` |
| B. 手动改文件 | 用编辑器打开 `project.config.json`，把 `"appid": "touristappid"` 改成 `"appid": "wx1a2b3c4d5e6f7890"` | ★★ 注意别加多余空格，JSON 不允许 |

> ⚠️ **用游客 AppID（`touristappid`）无法使用云开发**。必须换成真实 AppID 或测试号 AppID
> 才能看到「云开发」按钮并部署云函数。这一点在第 3 步之前务必完成。
>
> 另外 `project.private.config.json` 是本地个人配置，已在 `.gitignore` 里忽略，
> 工具可能会在这里覆盖 AppID —— 如果发现改完又变回去了，优先检查这个文件。

## 3. 创建云开发环境并填写 ENV_ID

### 3.1 拿到环境 ID

1. 开发者工具 → 工具栏「云开发」→ 进入云开发控制台
2. 左上角环境名称旁的下拉框 → 「设置」→ 记下**环境 ID**（形如 `campus-time-bank-1g2h3i4j5k6l7m`）
3. 如果有多个环境，**确认当前选中的是你要用的那一个**

### 3.2 填到 `Campus Time Bank/envList.js`

打开 `Campus Time Bank/envList.js`，只改这一行：

```js
// ============================ 必填 ============================
const ENV_ID = 'campus-time-bank-1g2h3i4j5k6l7m' // ← 填你的环境 ID
```

### 3.3 为什么填了 ENV_ID 就自动接真实后端？

`envList.js` 底部有一行自动判断，**不需要手动改任何开关**：

```js
const MOCK_OVERRIDE = null   // null = 由 ENV_ID 是否为空自动决定
const MOCK = MOCK_OVERRIDE === null ? !ENV_ID : !!MOCK_OVERRIDE
```

| `ENV_ID` | `MOCK_OVERRIDE` | `MOCK` | 实际行为 |
|---|---|---|---|
| `''`（空） | `null` | `true` | 走 `utils/mock.js` 离线模拟数据 |
| 非空字符串 | `null` | `false` | 走真实云函数 |
| 任意 | `true` | `true` | **强制**离线预览（调试 UI 用） |
| 任意 | `false` | `false` | **强制**真实后端（辅助排查「是不是 mock 在骗我」） |

`app.js` 在 `onLaunch` 里调用 `cloud.initCloud()`，而 `initCloud()` 内部有一道守卫：

```js
function initCloud() {
  if (_inited || MOCK || !envId) return      // ← MOCK 模式下直接返回，不初始化
  wx.cloud.init({ env: envId, traceUser: true })
}
```

这样离线模式下不会因为 `wx.cloud` 未初始化而报错。**判断是否真的连上了云环境**：
重新编译后看控制台，如果打印 `[cloud] 云开发已初始化, env = xxx` 就是真连上了；
如果打印绿色警告「当前为【离线预览模式】」说明还在跑 mock。

## 4. 部署云函数

本项目共 **9 个业务云函数**：`login` `skill` `order` `wallet` `user` `message` `admin` `initdb`。

### 4.1 第一步：先同步共享层

在**项目根目录**打开终端（或开发者工具的「终端」面板），执行：

```bash
node tools/sync-shared.mjs
```

期望输出：

```
同步共享代码 → 9 个云函数
源：cloudfunctions/_shared  (index.js)

  ✓ login/shared/  (1 个文件)
  ✓ skill/shared/  (1 个文件)
  ...（共 8 行）

完成：共写入 8 个文件。
提醒：请在微信开发者工具中对每个云函数右键「上传并部署：云端安装依赖」。
```

### 4.2 为什么必须有这一步（答辩会问）

微信云开发的**每个云函数都是独立打包上传的**：当你上传 `cloudfunctions/order/` 时，
云端打包器只会收集 `cloudfunctions/order/` 目录以内的文件上传，**无法 `require('../_shared')` 去引用兄弟目录**。
如果代码里写 `require('../_shared')`，部署后会直接报错：

```
Error: Cannot find module '../_shared'
```

所以本项目采用「**单一源码 + 构建同步**」的分发方案：

```
cloudfunctions/_shared/index.js          ← 唯一手写的源文件（数据库、工具函数、常量）
              │
              │  node tools/sync-shared.mjs
              ▼
cloudfunctions/login/shared/index.js     ← 自动生成的副本
cloudfunctions/skill/shared/index.js     ← 自动生成的副本
cloudfunctions/order/shared/index.js     ← 自动生成的副本
...（8 个函数各一份）
```

所有云函数的代码统一写 `require('./shared')`，指向同目录下的 `shared/`，云端就能正常解析了。

> **结论**：`cloudfunctions/_shared/index.js` 是唯一需要手改的共享文件；
> 改完**必须重跑 `node tools/sync-shared.mjs`**，然后再重新上传所有受影响的云函数。
> 各函数目录下的 `shared/index.js` 是生成物，**不要手改**，下次同步会被覆盖。
> `node tools/check-project.mjs` 会检查每个函数的 `shared/index.js` 是否存在，缺失时给出警告。

### 4.3 第二步：逐个上传部署

在开发者工具左侧的「资源管理器」中展开 `cloudfunctions/` 目录，对**每一个**云函数目录：

1. **右键**该目录（如 `login`）
2. 选择「**上传并部署：云端安装依赖（不上传 node_modules）**」

> ⚠️ 一定要选「**云端安装依赖**」这一项。因为每个云函数的 `package.json` 里声明了
> `"wx-server-sdk": "~2.6.3"`，选中「云端安装依赖」后微信会在云端 `npm install`；
> 如果选成「上传所有文件」且本地没装依赖，运行时会报 `Cannot find module 'wx-server-sdk'`。

**建议上传顺序**（`initdb` 放最后，因为前面的函数部署好才能验证）：

| 顺序 | 云函数 | 说明 | 预计耗时 |
|---|---|---|---|
| 1 | `login` | 登录与用户资料，最基础的依赖 | 30~60 秒 |
| 2 | `skill` | 技能广场 | 30~60 秒 |
| 3 | `order` | 订单与时间币事务核心 | 30~60 秒 |
| 4 | `wallet` | 时间币 | 30~60 秒 |
| 5 | `user` | 个人中心 / 信用 / 徽章 | 30~60 秒 |
| 6 | `message` | 聊天 / 通知 | 30~60 秒 |
| 7 | `admin` | 管理端 | 30~60 秒 |
| 8 | `initdb` | 一键初始化（最后用） | 30~60 秒 ⚠️ **需先把超时时间改到 60 秒**，见下 |

每次上传后看开发者工具右下角的「上传成功」提示，或者到
「云开发控制台 → 云函数」列表里确认 8 个函数都在，且「最后更新时间」是刚才。

### 4.4 验证部署

重新编译小程序。在「技能广场」页面下拉刷新，如果还是模拟数据，检查：

1. `envList.js` 的 `ENV_ID` 是否真的填了非空值
2. 控制台是否出现了 `云开发已初始化, env = xxx`
3. 「云开发控制台 → 云函数 → login → 日志」里是否有调用记录

## 5. 初始化数据库

项目使用 **14 个数据库集合**（详见 [数据库设计.md](数据库设计.md)）。初始化有两种方式，**任选一种**。

### ⚠️ 先做这一步：把 `initdb` 的超时时间改到 60 秒

**云函数默认超时是 3 秒，而 initdb 要写上百条种子数据，跑完需要 30~60 秒。**
不改的话会出现：

```
Invoking task timed out after 3 seconds  (statusCode 433)
```

改法：**云开发控制台 → 云函数 → `initdb` → 配置 → 超时时间 → 60 秒**（保存即可，不用重传代码）

> 💡 **不改也能跑完**：initdb 是**幂等**的 —— 每个种子文档写入前先探测是否已存在，
> 已存在的跳过。所以超时只会中断在中间，**再点几次「云端测试」就会从断点继续**，
> 每次都能多写一批，点几次就全写完了。实在不想改配置，就多点几次。

### 方式 ① 用 `initdb` 云函数一键初始化（强烈推荐）

这是最省事的方式：一次调用会创建全部 17 个集合，并写入分类、全局配置、轮播图，
以及一整套演示用户 / 技能 / 订单 / 评价 / 流水数据（方便你立刻看到有数据的页面）。

**操作步骤：**

1. 打开「云开发控制台 → 云函数」
2. 找到 `initdb`，点击右侧「**测试**」
3. 在「测试参数」输入框中填入：

   ```json
   { "action": "init" }
   ```

4. 点击「**运行测试**」

   > **★ 关于权限：为什么控制台里没有登录态也能跑通？**
   >
   > 云开发控制台本身就是**开发者（root）权限** —— 能打开它的人可以直接在
   > 「数据库」页面增删任何集合。所以在云函数里再拦一道挡不住任何真实攻击，
   > 只会让合法运维卡死。因此 `initdb` 的鉴权分两层：
   >
   > | 调用来源 | 行为 |
   > |---|---|
   > | **控制台**（云端测试，无 `OPENID`） | 一律放行 |
   > | **小程序**（有 `OPENID`） | `users` 为空 → 放行；无管理员 → 引导模式放行；已有管理员 → 要求调用者是管理员 |
   >
   > 这样设计同时避开了两个死锁：**没有管理员 → init 被拒 → 引导不出管理员**，
   > 以及 **有了管理员之后控制台再也调不动 init**（控制台没有登录态）。
   >
   > `setAdmin` 同理：小程序调用时仅限「系统尚无管理员」，防止提权；
   > 第一个管理员产生后，后续授权走管理端「用户管理 → 设为管理员」。

   > **⚠️ 但鉴权通过之后还有一道坎：超时时间。**
   > 微信云函数的 **`timeout` 默认只有 3 秒**（[官方文档](https://developers.weixin.qq.com/doc/oplatform/openApi/cloudbase-common/scf-management/api_getuploadfuntionconfig.html)：
   > 可选 1–300 秒，默认 3 秒）。`init` 要建 17 个集合 + 写 60 多条种子数据，
   > 首次冷启动下 3 秒必然不够，会返回：
   >
   > ```json
   > {"errorCode":-1,"errorMessage":"Invoking task timed out after 3 seconds","statusCode":433}
   > ```
   >
   > **解决：把 `initdb` 的超时时间调到 20 秒**
   > （云开发控制台 → 云函数 → 点 `initdb` → 「函数配置」/「版本与配置」→ 超时时间 → 20 → 保存）。
   >
   > 好消息是 **`init` 是幂等的**：它按 `_id` 逐条跳过已存在的数据。
   > 所以就算第一次超时中断了，**直接再跑一次就会从断点继续**，不会重复插入。
   > 实在改不了超时，就多点几次「运行测试」，每次都会往前推进一批。

5. 在下方「运行结果」里看到类似输出即成功：

   ```json
   {
     "code": 0,
     "msg": "ok",
     "data": {
       "created": ["users", "categories", "skills", "orders", "reviews",
                   "wallet_logs", "credit_logs", "chats", "messages",
                   "notices", "reports", "banners", "config"],
       "existed": [],
       "seeded": { "categories": {"inserted": 10, "skipped": 0}, "...": {} },
       "summary": { "users": 7, "skills": 8, "orders": 6, "...": 0 }
     }
   }
   ```

6. 回到「云开发控制台 → 数据库」，确认左侧出现了 17 个集合

> **`init` 是幂等的**：重复执行不会重复插入（脚本按固定 `_id` 探测后再写），
> 所以你可以放心多点几次。它也有**安全护栏**：当 `users` 集合**非空**时，
> `init` / `clear` 会被拒绝执行，防止误操作把已有数据清掉。
> 第一次初始化时 `users` 是空的，所以能直接跑。
>
> 想先清空再重建（例如演示前恢复初始状态），传 `{"action": "clear"}`：
> 它会清空业务集合，但**保留 `users` 里的管理员账号**，也保留 `categories` / `banners` / `config`
> 这三个基础配置集合（否则首页会空掉）。

### 方式 ② 在控制台手动建集合

如果你不想跑 `initdb`（例如想自己控制演示数据），按下面的清单手工创建。

**操作步骤：**

1. 「云开发控制台 → 数据库 → 集合管理 → + 新建集合」
2. 依次创建以下 17 个集合，**名称必须完全一致**（区分大小写，全小写 + 下划线）
3. 建完后至少手动往 `config` 集合插入一条 `_id` 为 `global` 的文档，否则读取配置会走默认值：

   ```json
   {
     "_id": "global",
     "registerBonus": 5,
     "orderExpireHours": 24,
     "confirmExpireHours": 72,
     "minCreditToOrder": 60,
     "serviceFee": 0,
     "hotCategories": [],
     "aboutUs": "校园时间银行 —— 大学生技能互助平台"
   }
   ```

**17 个集合清单：**

## 6. 集合权限配置表

微信云开发的每个集合都有独立的「数据权限」设置，**这是本项目安全模型的核心**。
默认情况下集合权限是「仅创建者可读写」，本项目**必须按下面的表逐一调整**。

### 6.1 操作路径

「云开发控制台 → 数据库 → 选中集合 → 右侧「权限设置」→ 选择对应权限 → 保存」

可选权限有四种：

| 权限名称 | 含义 |
|---|---|
| 仅创建者可读写 | 只能读写 `_openid` 等于自己的记录 |
| 所有用户可读，仅创建者可读写 | 所有人可读，只有创建者能写 |
| 所有用户可读，仅管理端可写 | 所有人可读，只有云函数（管理端）能写 |
| **仅管理端可读写** | 客户端**完全不可访问**，只能通过云函数读写 |

### 6.2 配置表（13 行）

| 集合名 | 权限设置 | 原因 |
|---|---|---|
| `users` | **仅管理端可读写** | 用户文档里含 `coins` / `frozenCoins` / `creditScore`等可直接变现的字段。若允许客户端写，任何人改一行就能给自己刷时间币，整个经济系统立刻失效。所有读写（登录、改资料、扣加币、改信用分）都走云函数。 |
| `categories` | **仅管理端可读写** | 分类由管理员维护（`admin.saveCategory`），普通用户只通过 `skill.categories` 这个云函数读，不需要直连数据库。 |
| `skills` | **仅管理端可读写** | 技能含 `status`（上架/下架/违规）、`isTop`、`orderCount` 等审核与统计字段。若客户端可写，发布者可以自己把违规技能改回「上架」、或把自己置顶。发布/编辑/下架全部走 `skill.create` / `skill.update` / `skill.remove`。 |
| `orders` | **仅管理端可读写** | 订单直接对应时间币的冻结与结算。客户端若能改 `status`，就能把「待接单」改成「已完成」骗过结算，或把 `amount` 改成 0。全流程必须由云函数状态机驱动。 |
| `reviews` | **仅管理端可读写** | 评价影响信用分与综合评分。写入走 `user.reviewCreate`（服务端校验订单已完成、未重复评价），回复走 `user.reviewReply`（校验只有被评价人本人能回复）。 |
| `wallet_logs` | **仅管理端可读写** | 时间币流水是账本，只能由 `addWalletLog()` 由云函数追加，客户端必须只读（通过 `wallet.logs` 拉取）。允许客户端写入等于可以伪造账目。 |
| `credit_logs` | **仅管理端可读写** | 信用分变动记录同理，只能由 `changeCredit()` 写入，防止伪造「我没有被扣分」。 |
| `chats` | **所有用户可读，仅创建者可写** | ★ 例外一：`chats` 会被客户端 `watch`（虽然聊天室主要 watch 的是 `messages`，但会话信息也需要可读）。**写入仍强制走 `message.openChat` 云函数**（服务端保证 `members` 是升序排列的唯一二人组合，避免同一对用户产生多个会话）。 |
| `messages` | **所有用户可读，仅创建者可写** | ★ 例外二（**最关键的一条**）：客户端实时聊天用的是 `db.collection('messages').where({chatId}).watch()`，而 `watch` 长连接**必须**有客户端的读权限，权限为「仅管理端可读写」时 `watch` 会直接报错。所以这个集合必须开放读。**但写入不能开放**：`message.send` 云函数会校验「发送者与接收者确实在同一个 `chats.members` 里」，防止任意用户往别人会话里塞消息。注意集合权限里的「仅创建者可写」只是数据库层的兜底，业务上的写入一律走云函数。 |
| `notices` | **仅管理端可读写** | 系统通知的接收者与内容由服务端决定（订单动态、审核结果、信用变动、举报结果）。客户端只需通过 `message.notices` 读取、`message.readNotice` 标记已读。 |
| `reports` | **仅管理端可读写** | 举报内容不能让被举报人看到（否则会报复），必须由云函数按 `requireAdmin()` 过滤后返回给管理员。客户端提交走 `skill.report`。 |
| `banners` | **仅管理端可读写** | 轮播图是运营内容，由管理员在 `settings` 页维护。 |
| `config` | **仅管理端可读写** | 全局配置（注册赠送币数、超时时长、最低信用分、手续费）是全平台经济参数，一旦客户端可改，任何人都能把自己变成「注册送 9999 币」。客户端通过登录接口返回的 `config` 字段获得。 |

### 6.3 为什么非要给 `chats` / `messages` 开读权限？（答辩必答）

云开发的 `db.collection().watch()` 实时监听是**客户端直接连数据库**的长连接，
它读取数据的身份是「当前小程序用户」，而不是云函数。所以：

- **权限为「仅管理端可读写」时** —— 客户端连 `db.collection('messages').get()` 都拿不到数据，
  `watch()` 会立即 `onError`（报权限不足），实时聊天功能完全不可用。
- **权限为「所有用户可读，仅创建者可写」时** —— `watch()` 能正常建立，但客户端仍**只能读**，
  想发消息必须调 `message.send` 云函数，服务端在那里校验成员身份。

**消息安全是怎么保证的？**（三层）

1. **数据库层**：`messages` 权限不含「所有用户可写」，客户端无法直连写入。
2. **云函数层**：`message.send` 会先查 `chats` 文档，断言 `chatId` 存在、
   且调用者与 `toId` 都出现在 `chats.members` 数组里；不满足直接抛 403。
3. **展示层**：聊天室页面只 `watch` 自己参与的 `chatId`，
   `where({ chatId })` 条件让返回的 `snapshot.docs` 天然局限于该会话。

> ⚠️ **隐私提醒**：`messages` 开放读权限意味着**理论上**任何用户都可以读取全部消息文档
> （只要构造出查询）。这是为了 `watch` 实时能力付出的代价，也是本设计相对完整的
> 「服务端转发 + 订阅」方案的一个已知取舍。项目在 `docs/答辩材料.md` 的「不足与改进方向」
> 里明确写入了这一点：生产环境应改为「云函数定时拉取 + 客户端轮询自己的 toId」
> 或使用 `wx.cloud.callFunction` + 长轮询，以彻底关闭 `messages` 的读权限。

## 7. 把自己设为管理员

管理端分包 `packageAdmin/` 的 10 个页面都需要 `role === 'admin'`。

### 7.1 先拿到自己的 openid

1. 编译运行小程序，让它在首页完成一次静默登录
2. 「云开发控制台 → 数据库 → `users` 集合」→ 找到昵称是自己、或 `createTime` 最新的一条
3. 复制该文档的 `_openid` 字段值（形如 `oX7aBcDeFgHiJkLmNoPqRsTuVwX`）

> 也可以用「云开发控制台 → 云函数 → login → 日志」看到本次调用的 `OPENID`。

### 7.2 方式一：调 `initdb` 的 `setAdmin`（推荐）

1. 「云开发控制台 → 云函数 → `initdb` → 测试」
2. 测试参数填入：

   ```json
   { "action": "setAdmin", "openid": "oX7aBcDeFgHiJkLmNoPqRsTuVwX" }
   ```

3. 点击「运行测试」，返回 `{"code":0,"msg":"ok","data":{"ok":true}}` 即成功

### 7.3 方式二：直接改数据库字段

1. 「云开发控制台 → 数据库 → `users` → 找到自己的那条记录 → 编辑」
2. 把 `role` 字段的值从 `"user"` 改成 `"admin"`
3. 保存

> ⚠️ **改完要清缓存**：`app.globalData.isAdmin` 与 `isAdminUser()` 都带缓存，
> 改完数据库后需要**重新编译小程序**（或在「我的」页面下拉刷新触发 `refreshUser`），
> 否则当前会话里仍然判定为非管理员。

### 7.4 验证管理员身份

1. 重新编译 → 进入「我的」页面
2. 页面底部会出现「管理后台」入口
3. 点击进入 `packageAdmin/pages/dashboard/dashboard`，能看到 7 张图表即成功

**非管理员会怎样？** `packageAdmin/utils/guard.js` 的 `requireAdmin(this)` 会
`toast('无管理员权限')` 并在 900ms 后 `navigateBack`；如果当前页面栈只有一页
（比如开发者工具直接编译进 dashboard），`navigateBack` 会失败，
此时降级 `reLaunch` 到「我的」页，避免出现白屏死页。

## 11. 云函数附加配置说明

云开发的部分开放接口需要**显式声明权限**，否则调用会报
`errCode: -604100 无权限` 或 `openapi.permission denied`。项目已经把这些配置写在了
各云函数目录的 `config.json` 里，**上传部署时会自动生效，无需手动操作**，
但你需要知道它们的存在，出问题时才知道去哪里看。

| 云函数 | 配置文件 | 配置内容 | 用途 | 缺失时的表现 |
|---|---|---|---|---|
| `login` | `cloudfunctions/login/config.json` | `permissions.openapi: ["phonenumber.getPhoneNumber"]` | 手机号快速验证（`bindPhone` action） | 点「一键绑定手机号」报 `-604100 无权限` |
| `message` | `cloudfunctions/message/config.json` | `permissions.openapi: ["subscribeMessage.send"]` | 发送订阅消息 | 订阅消息静默失败（被 `try/catch` 吞掉），功能不中断 |
| `order` | `cloudfunctions/order/config.json` | `permissions.openapi: ["subscribeMessage.send"]` **+** `triggers: [{ name: "orderAutoTask", type: "timer", config: "0 */10 * * * * *" }]` | ① 订单域自己也要发订阅消息（下单/接单/完成/到账四个节点）② 每 10 分钟扫描并处理超时订单 | ① 订阅消息静默失败；② 超时订单只能靠用户调 `order.counts` 时的惰性检查兜底 |

`order/config.json` 的完整内容：

```json
{
  "permissions": {
    "openapi": [
      "subscribeMessage.send"
    ]
  },
  "triggers": [
    {
      "name": "orderAutoTask",
      "type": "timer",
      "config": "0 */10 * * * * *"
    }
  ]
}
```

> ⚠️ **`order` 也需要 `subscribeMessage.send` 权限**，不要只记得 `message` 函数 ——
> 四个订阅消息触发点（下单通知卖家、接单通知买家、完成通知买家、到账通知卖家）
> 全部写在 `cloudfunctions/order/index.js` 的 `sendSubscribe()` 调用里。

> **`0 */10 * * * * *` 是 7 位 Cron 表达式**（微信云开发用的是 7 位：秒 分 时 日 月 周 年），
> 含义是「每 10 分钟的第 0 秒执行一次」。它对应 `cloudfunctions/order/index.js` 入口里的：
> ```js
> if (event.action === 'autoTask' || event.Type === 'Timer') {
>   return actionAutoTask()      // 定时触发时没有 OPENID，所以这个分支不调用 requireUser()
> }
> ```
> 定时触发时 `event` 形如 `{ Type: 'Timer', TriggerName: 'orderAutoTask' }`，
> **没有 OPENID**，所以这条分支刻意不做登录校验，只做全库的超时订单处理。

### 11.1 订单超时的「双保险」

定时触发器**不保证准时**（云开发存在触发抖动，函数冷启动也有延迟），所以超时处理做两层：

1. **定时触发器**（`order.autoTask`，每 10 分钟）：批量扫描超时订单并处理，不依赖任何用户在线 —— 这是主路径。
2. **惰性检查**（`order.counts` 被任意用户调用时）：顺手检查并处理与自己相关的超时订单 —— 这是兜底。

两条路径都调用同一组内部函数（`closeAndRefund` / `settleOrder`），且内部都有状态断言，
因此**重复执行是幂等的**（第二次会因状态不符直接跳过），不会重复退款或重复结算。

### 11.2 查看触发器是否生效

「云开发控制台 → 云函数 → order → 触发器」，应能看到名为 `orderAutoTask`、
周期为 `0 */10 * * * * *` 的触发器。想临时停用就点「删除」，
答辩结束后建议停用以免长期占用调用额度。

## 内部账户入口（隐藏）

内部账户（校方 / 运维）用**账号密码**登录，**不需要绑定微信号**。

它的入口**不在明面上** —— 普通学生看不到任何相关字样。原因有两个：

1. 摆在「我的」页等于告诉所有学生「这里有个特权入口」，既不专业也会引来试探；
2. 学生界面上出现「内部账户登录」，答辩时一定会被问。

### 怎么进

| 你的身份 | 进入方式 |
|---|---|
| 微信已被授权为**管理员 / 调试员** | 「我的」页 → **内部账户登录**（正常可见） |
| 新校方（微信还没有任何权限） | 「关于与规则」页 → **长按底部的版本号** |

第二种是给**交接**用的：新一届校方拿到账号密码时，他的微信还不是管理员，
如果入口只放在管理后台里，他就永远进不去。

### 账号

首次部署跑 `{"action":"init"}` 会种入两个内部账户：

| 账号 | 初始口令 | 角色 |
|---|---|---|
| `admin` | `V7mK2qXp` | 管理员 |
| `debugger` | `T4nR9wZb` | 调试员（校方） |

> ⚠️ **正式使用前必须改口令。** 它们写在种子数据里，会随仓库一起公开。
> 改法：改 `cloudfunctions/initdb/index.js` 的 `SEED_ACCOUNTS` 后重跑
> `init`（用 repair 模式覆盖），或直接在云开发控制台修改 `accounts` 集合里的
> `salt` / `passwordHash`（用 `_shared` 的 `hashPassword(新口令, 新盐)` 现算）。

### 改口诀

隐藏入口 = `Campus Time Bank/pages/about/about.wxml` 里版本号的 `bindlongpress`。
改这里就要回来改本节的说明。
